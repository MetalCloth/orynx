# Local Brave browser through Playwright MCP

Oryn's `playwright` MCP now targets the user's existing Brave profile. Oryn's model remains the planner; Playwright MCP provides browser observations and actions. Firecrawl remains a separate remote browser, and `computer_*` remains the path for native desktop controls.

## What Oryn sees

`browser_snapshot` returns a structured ARIA-style snapshot of the current web page, with roles, accessible names, text, and references such as `button "Search" [ref=e8]`. Oryn can pass a reference to a Playwright action. Page-changing actions return updated page state; references are only valid for the snapshot they came from. A local evaluation of `@playwright/mcp@0.0.85` found that snapshots include content from `aria-hidden="true"` subtrees. Oryn removes those nodes and their descendants from unscoped snapshots, snapshot sections returned after actions, and `browser_find` results. This cleanup changes Oryn's text observation only; the page and browser DOM remain unchanged. To inspect an `aria-hidden` subtree deliberately, call `browser_snapshot` with an explicit `target` CSS selector or element reference; that scoped snapshot preserves the subtree. For example, an ordinary snapshot gives the page overview, while `browser_snapshot(target="main")` includes hidden nodes within the targeted subtree. `aria-hidden` is an accessibility-tree state, not a CSS visibility rule, so this cleanup can also omit visually displayed content. The snapshot remains a semantic DOM view, not a complete representation of the rendered page or assistive-technology experience.

The native tool result also prefixes the active page snapshot with the browser's open-tab titles and URLs. Oryn now removes that Open tabs section from page and action results. Use the dedicated `browser_tabs` tool when the complete tab list is needed.

This is a browser-provided page snapshot, not Linux AT-SPI. It does not describe Brave's menus or other desktop apps. Playwright can also report CSS-pixel boxes. Screenshot tools remain hidden because Oryn's MCP adapter currently drops image blocks; use the existing desktop screenshot path for visual questions about the visible tab.

Official references: [Playwright snapshots](https://playwright.dev/mcp/snapshots), [interaction tools](https://playwright.dev/mcp/tools/interaction), and [vision mode](https://playwright.dev/mcp/vision-mode).

## How Oryn connects

The local launcher reads Brave's current `DevToolsActivePort` file under `${XDG_CONFIG_HOME:-~/.config}/BraveSoftware/Brave-Browser`. When Playwright is enabled, Oryn starts one user-level systemd service, `oryn-playwright-bridge.service`, running the pinned `@playwright/mcp@0.0.85` HTTP server at `http://127.0.0.1:8931/mcp`. A small anchor client stays connected inside the service and keeps its shared CDP browser alive when Oryn exits or restarts. On Oryn's next start, it reuses that service if the Brave endpoint still matches, instead of opening another browser-debugging connection.

If Brave's endpoint is missing or its TCP listener is unavailable, Oryn refuses to start the service. If Brave restarts and the endpoint changes, Oryn stops the old service and starts one replacement; Brave may ask for approval for that new connection. This does not launch a headless, isolated, or temporary browser. The endpoint file is read directly because this Brave currently answers `/json/version` with HTTP 404.

Brave's **Allow remote debugging?** dialog grants broad access to the browser session. It is still per browser-debugging connection; the persistent anchor is intended to keep that connection open across Oryn restarts. Normal Oryn exit does not stop this service. Turning Playwright off in Oryn stops it. The service makes one read-only tab-list request when it starts to establish the shared browser session, then holds that client open; it does not navigate or change a page.

The HTTP MCP endpoint binds only to loopback and requires a random token in the Authorization header. The token is stored in `~/.mini-hermes/playwright-bridge-token` with mode 0600, reused across Oryn restarts, rotated when the service is replaced, and removed when disabled. Missing or wrong tokens receive HTTP 401; browser Origin headers are rejected. Programs running as the same Linux user can read the token, so this is not isolation from your own account. The HTTP `connected` status means Oryn reached this MCP service; the service's first browser operation may still trigger Brave's approval dialog. Inspect or stop the service with:

```bash
systemctl --user status oryn-playwright-bridge.service
journalctl --user -u oryn-playwright-bridge.service
systemctl --user stop oryn-playwright-bridge.service
```

## Oryn's tool boundaries

- The `playwright` preset is the local Brave route and is enabled through Oryn's existing MCP setting.
- `browser_snapshot`, `browser_find`, tab listing, and selected diagnostics are read-only; actions such as clicking and typing require Oryn approval. Tab selection and closing require approval. Creating a tab at a private, local, or unverified URL also requires approval; public URLs follow the existing navigation policy.
- Private or unverified navigation targets remain guarded by the existing URL policy.
- Browser Use is not used. The native `browser_*` tools backed by Firecrawl remain separate from this local Brave session.
- Local browser calls bind the turn to the local desktop route. They are not automatically replayed if a result is uncertain.
- Browser text is untrusted page content, not instructions to Oryn.

## Validation status

Validation covers endpoint parsing, service reuse across Oryn restarts, one-time replacement after Brave restarts, refusing unknown listeners, and the HTTP route. Live checks confirmed that Oryn loaded Playwright tools after restarting, read tab and DOM data from the existing Brave profile, and that the service's anchor kept the Brave CDP socket established while Oryn connected. The browser snapshot exposed the Chrome remote-debugging page's checked setting and loopback listener; the Netflix snapshot was sparse. No page settings were changed.

The first reconnect after installing authentication replaces the older unprotected service once. This can trigger one new Brave consent prompt. Normal Oryn reconnects then reuse the authenticated service.

Authentication validation confirmed HTTP 401 for missing/wrong tokens, HTTP 403 for browser Origin headers, and successful MCP discovery of 22 tools with the token. An earlier replacement connection timed out while opening Brave's debugging WebSocket. The anchor rejects the adapter's `MCP server reported a tool error:` prefix as failure instead of logging a false connection success. It does not retry automatically.

The follow-up live check on 2026-11-20 succeeded through the authenticated bridge: Oryn listed 10 existing Brave tabs and read the current page's accessibility snapshot. After that client exited, a separate Python process connected and repeated both reads successfully. The bridge retained the same service PID and credential after both clients disconnected. The earlier timeout did not reproduce, so its cause remains unconfirmed. These checks did not navigate, switch tabs, click, type, or change page settings; page-changing actions and a Brave restart were not tested in this follow-up.

The user subsequently confirmed that repeated Allow prompts appeared inside Brave. A follow-up checked the actual established debugging socket, rather than only the bridge PID: its local port, Node process, and file descriptor remained unchanged through six tab reads across three MCP clients, including after each client closed. A separate check ran three consecutive conversation-loop turns with scripted model responses and real MCP tab reads; the same socket remained established through all three turns and after the client closed. Socket polling during the first check observed no changes at 100 ms intervals. No browser restart or bridge replacement was performed.

At the user's request, the check was repeated while they watched Brave: three conversation-loop turns with scripted model responses and real tab reads, followed by a tab read from a fresh MCP client, all succeeded. The original debugging socket remained established throughout, with no socket changes observed at 100 ms intervals. The user confirmed that no Allow popup appeared. Reuse across turns and client reconnects is therefore verified for that running Brave session. The cause of the earlier repeated prompts remains unknown.

Brave was then restarted through its native address bar with `chrome://restart/`. Its window PID and debugging endpoint changed, and its tabs were restored. On reconnect, Oryn replaced the old bridge service and saved the new endpoint. Three tab reads and a page accessibility snapshot succeeded; the tab list settled at six tabs as the session restored. A fresh MCP client then read the tabs successfully, retaining the same post-restart debugging socket even after closing. This verifies recovery after a Brave restart and bridge replacement. The user confirmed exactly one Brave approval prompt during this restart test. Together with the earlier prompt-free turn and client-reconnect checks, this validates one approval for the replacement browser connection and reuse afterward in the tested session.

The full Python suite passed all 277 tests, including the bridge lifecycle and HTTP authentication checks; all six offline evaluations passed. The hosted-preset test now excludes the local Playwright HTTP connection when counting the nine hosted services.

On 2026-11-20, a deterministic scripted conversation-loop evaluation used a local HTTP form fixture in a named isolated context. It did not send network requests or save submitted data. The snapshot omitted the form while it had the HTML `hidden` attribute, but included a role and text inside the fixture's `aria-hidden="true"` subtree. The fixture click was first denied and did not reveal the form; a scripted approval then allowed the click, text entry, email fill, option selection, and submit. Submission count reached one. Reusing the old submit reference after the DOM changed returned an error in 8.17 ms and did not submit again. The approval decisions were supplied by a test callback, not a live Oryn approval dialog.

Twenty identical fixture snapshots, before the result cleanup, measured 21.84 ms median latency and 23.54 ms p95 (20.20–26.06 ms). The full result measured 2,069 UTF-8 bytes and 927 estimated `o200k_base` tokens; the fixture page section measured 556 bytes and 168 tokens. The difference came from the open-tab metadata prefixed to the page snapshot. These are small local fixture baseline measurements, not a benchmark across sites or models. Focused adapter regression checks now cover removal of the tab preamble and hidden subtree, preservation of a scoped inspection, and leaving the dedicated tab-list result intact. A fresh MCP client reconnected, discovered the Playwright tools, and read a temporary default-context fixture tab; that tab was removed afterward. No Brave restart was part of this run.

The same evaluation found that `browser_tabs` had treated every action as safe: local `new`, `select`, and `close` all bypassed Oryn approval even though local `browser_navigate` was guarded. The policy now leaves read-only `list` unapproved, applies the URL check to `new`, and requires approval for `select`, `close`, and unknown actions. A focused regression test covers these cases. The scripted evaluation used automatic approval callbacks, so the live prompt UI for the newly guarded tab actions was not manually exercised.

After the policy change, both focused MCP policy tests passed. A broader `src.tests.test_mcp` rerun was interrupted after more than a minute while executing `test_browser_login_reports_its_url_without_printing_over_the_tui`; that run has no pass/fail result. The 277-test full-suite result above predates this policy edit.

A follow-up compatibility check on 2026-11-20 ran cached `@playwright/mcp@0.0.86` in a separate headless, isolated Chrome process with local-only fixtures. It still returned the role and text from an `aria-hidden="true"` subtree. Clicking the returned hidden-button reference succeeded and fired the fixture's handler. With two fixture tabs open, the inactive tab's title and URL appeared in the active-page snapshot; requesting the `main` subtree did not remove that metadata (473 characters in both responses). The check did not connect to or change the user's Brave session. The newer package therefore does not fix either observed limitation in this reproduction, so Oryn remains pinned to 0.0.85.

A source and adapter audit on 2026-11-21 found that `browser_find` also searches the AI-mode accessibility snapshot, but returns an unfenced tree snippet rather than a `### Snapshot` section. The existing cleanup therefore missed hidden matches returned by search. Oryn now filters that result shape too. The same audit narrowed open-tab removal to a leading preamble, so a later page-provided heading with the same text is preserved. A regression also covers page text that merely quotes the literal `[aria-hidden="true"]` marker. Six focused adapter tests passed. This pass did not run a fresh live Brave check; no local Playwright MCP tool was exposed in the Codex session.

Playwright's AI snapshot uses an `aria-or-visible` policy: it includes elements exposed through ARIA or considered visually visible, and marks `aria-hidden` nodes in the output. Its visibility rules treat `opacity: 0` as visible. As a result, the snapshot and Oryn's cleanup are not a pixel-accurate hidden-versus-visible classifier: `aria-hidden` content may be visible on screen and transparent elements may still appear. Closed disclosure content can also be absent until opened. Dynamic pages are point-in-time observations; use `browser_wait_for` for known text transitions and capture a fresh snapshot after page changes because refs are tied to prior snapshot state. Real-site interaction coverage remains limited to the previously documented checks; the deterministic local fixture covered click, text entry, form fill, selection, submit, and stale-ref rejection, but not a broad set of real-site forms or delayed-content patterns.
